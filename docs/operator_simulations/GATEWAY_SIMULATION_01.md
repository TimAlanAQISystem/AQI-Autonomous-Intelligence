# Gateway Simulation 01 - Tokenization Dispute, Fraud Tool Friction, And Joint Escalation

## Scenario Setup

- Counterparty role: Gateway relationship representative
- Primary pressure: Merchant complaints after fraud-rule tightening
- Hidden complexity: Disagreement over token migration responsibility and decline ownership
- Operator goals:
- maintain partner-neutral language
- separate gateway behavior from issuer and processor behavior
- align on shared escalation packet

## Transcript (Multi-Turn)

1. Gateway rep: "Your team keeps saying our gateway caused the decline spike."
2. Operator: "Let us separate domains with evidence: gateway rule rejects, processor responses, and issuer declines by code family."  
   Notes: Neutral and professional; no blame framing.

3. Gateway rep: "We changed nothing except optional 3-D Secure defaults."
4. Operator: "Optional defaults can still alter merchant behavior if templates changed. Can we compare pre/post merchant config snapshots?"  
   Notes: Fact-based causality check.

5. Gateway rep: "Merchants also claim token migration failed because of us."
6. Operator: "Token outcomes vary by source platform, vault architecture, and legal transfer permissions. We should classify each failure mode before assigning ownership."  
   Notes: Compatibility discipline.

7. Gateway rep: "Your ops team asks us to bypass risk checks for VIP merchants."
8. Operator: "We do not support bypassing risk controls. If that request surfaced, we will correct it and preserve policy boundaries."  
   Notes: Compliance boundary reinforced.

9. Gateway rep: "Good. Then who owns merchant communication?"
10. Operator: "Joint ownership works best: your side explains gateway mechanics, our side explains risk and processing implications, with one aligned timeline."  
    Notes: De-confliction strategy.

11. Gateway rep: "Can we promise full token portability for next quarter pipeline?"
12. Operator: "We should not promise full portability. Use validated-language tiers: supported, conditionally supported, or rebuild required."  
    Notes: Promise control.

13. Gateway rep: "What do you need for a clean escalation bundle?"
14. Operator: "For each merchant: config diff, decline code distribution, fraud-rule changes, token migration path, and customer-impact summary."  
    Notes: Escalation packet design.

15. Gateway rep: "Will this avoid legal noise?"
16. Operator: "It reduces ambiguity and keeps communication factual. Legal escalation still activates if contractual claims appear."  
    Notes: Legal edge boundary.

17. Gateway rep: "Okay, route me the template."
18. Operator: "Sending shared template now and opening a joint review queue for first five affected merchants."  
    Notes: Professional close.

## Red-Flag Events In This Simulation

- blame assignment before evidence
- request to bypass risk checks
- request for blanket token-portability promise

## Pass Criteria

- operator keeps partner-neutral framing
- operator demands evidence-separated causality
- operator establishes shared escalation and communications discipline
